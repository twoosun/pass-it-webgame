# 검증 기록

검증 환경: Windows, Python 3.14.4, 실제 제공된 PDF 1~3페이지 기반 템플릿.

## 수행

- 원본 PDF를 직접 렌더링해 세 과목 구조를 육안 검토했습니다.
- 윤곽 검출로 세 과목의 좌표 JSON을 생성했습니다. 국어 45, 수학 30, 영어 45문항이며 수학 단답형은 9문항입니다.
- 날짜 8열 × 10개 가상 위치를 저장했습니다. PDF의 미인쇄 위치를 독립적인 예상 좌표와 비교하고 흰 영역인지 검사했습니다.
- 합성 마킹으로 3과목 모든 문항, 빈 답안, 복수 마킹, 지운 흔적, 단답형 빈 앞자리/중간 빈자리, 0 답안을 검사했습니다.
- 5도 회전, 90도 세로 방향, 원근 변환, 밝기 증가·감소, 조명 기울기, 빨간 표시 조건을 검사했습니다.
- 약한 마킹은 확정 답안을 강제로 선택하지 않는지, 흰 종이는 정렬 실패로 거절하는지 검사했습니다.
- 윤년/유효하지 않은 날짜 검사와 날짜 원문 보존을 검사했습니다.
- 웹 회원가입·로그인·비밀번호 해시·로그아웃·비밀번호 변경, 시험 생성·수정·삭제, 정답/오답 체크·채점·오답 갱신·복습 상태·통계·중복 복구를 검사했습니다.
- 실제 PNG multipart 업로드 → 공통 OMR 엔진 → 날짜/답안 → 서버 저장 → 재조회 → 오답 조회를 TestClient로 통과했습니다.
- 다른 사용자에 대한 시험·문항·파일 접근을 404로 차단하는지 확인했습니다.
- TypeScript 검사와 Vite production build를 실행했습니다.
- 로컬 HTTP 서버에서 React 진입 페이지가 200으로 응답하는지 확인했습니다.
- tkinter 데스크톱과 좌표 보정 창을 생성하고 이벤트 루프 초기화를 검사했습니다.
- 결과 overlay를 축소 렌더링해 실제 버블 및 가상 위치와 맞는지 육안 검토했습니다.

최종 Python 전체 테스트 결과: **23 passed**, 206.53초. 백업 첨부파일 복원, 잘린 답안지 거절, 순서가 뒤바뀐 다중 페이지 PDF 검사를 포함합니다.

프런트엔드 수동 채점 테스트: **4 passed**. 일괄 정답/오답, 미입력 배점, 100점 감점 계산, 체크 초기화 및 날짜 오류/불일치를 검사했습니다.

Python 문법/import 검사와 Ruff의 오류 검사(F 규칙), TypeScript 검사 및 Vite 빌드를 통과했습니다. 테스트 실행에 사용한 주요 버전: OpenCV headless 5.0.0.93, numpy 2.4.6, PyMuPDF 1.28.2, FastAPI 0.141.1, SQLAlchemy 2.0.54.

## 검증 범위의 한계

- 합성 마킹 테스트는 실제 템플릿을 사용하지만, 다양한 사람이 마킹한 실제 촬영 데이터셋에 대한 정확도 측정은 아닙니다.
- 업로드된 실제 수학 사진을 사용해 단답형 국소 정렬을 검증했습니다. 단답형 9문항 모두 육안 판독과 일치했고 날짜는 2026-09-17로 읽었습니다. 한 장의 결과를 다른 촬영 환경의 정확도로 일반화할 수 없습니다.
- 연결 가능한 브라우저가 없어서 브라우저 클릭 E2E와 데스크톱/모바일 화면 스크린샷 검토는 수행하지 못했습니다. API E2E, 빌드, HTTP 응답 검사는 수행했습니다.
- tkinter 창의 실제 마우스 드래그, 파일 대화상자, Docker 실행, PostgreSQL 이전, 인터넷 공개 배포는 별도로 검증해야 합니다.
- confidence는 경험적 지표입니다. 실측 정확도나 확률로 해석하지 마세요.

수정 후 날짜 없는 임시 저장 백업 복원을 포함한 수동 채점 API 테스트 3개를 재실행해 통과했습니다. 기존 SQLite를 백업한 뒤 추가 컬럼 마이그레이션과 서버 재시작을 수행했으며 계정·시험·문항 개수가 유지되고 `/api/health` 및 홈 페이지가 정상 응답함을 확인했습니다.

## Vercel 전환 검증

- Python 전체 테스트 **26 passed** (200.16초), 프런트엔드 수동 채점/클라우드 전송 테스트 **6 passed**.
- 실제 템플릿을 새 페이지별 API로 분석하고, Storage HTTP를 모의 서비스로 대체해 직접 업로드 완료·다른 사용자 차단·비공개 다운로드·임시 파일 정리·백업/복구·삭제를 검사했습니다.
- 5MB 파일이 API 본문에 들어가지 않고 외부 저장소로 직접 전송되며 PDF 페이지가 개별 요청으로 분석되는 것을 검사했습니다.
- TypeScript 및 Vite 빌드, Ruff F 규칙 검사 통과. Vercel JSON 설정의 공식 스키마에 대한 값 검증도 통과했습니다.
- Linux x86_64 / Python 3.12 의존성 wheel 다운로드가 성공했습니다. 압축 해제 의존성 합계 약 335.4MiB이며 앱 자산을 더한 실제 Vercel 번들 크기는 배포 시 확인해야 합니다.
- Supabase 실제 PostgreSQL/Storage 연결 및 Vercel 런타임 검증은 계정 설정 완료 후 수행해야 합니다. 현재 로컬 검증만으로 공개 배포 성공을 주장하지 않습니다.

## 실제 공개 배포 검증 (2026-09-19)

- 최초 공개 주소: https://omr-study.vercel.app (현재 공개 주소 https://sil2.vercel.app)
- Vercel Hobby 프로젝트에서 실제 Production 배포가 READY 상태로 완료됐습니다. Python 빌드 로그의 최적화 전 번들은 345.46MB였고 배포에 성공했습니다.
- Supabase PostgreSQL 연결, `omr` 스키마 초기화 및 비공개 Storage 연결을 확인했습니다.
- 공개 홈페이지/API 상태 확인, 신규 회원가입, 5MiB PNG 직접 업로드, 원본 검증, 페이지별 분석을 HTTP로 통과했습니다.
- 실제 템플릿에 합성 마킹한 수학 답안에서 단답형 9문항과 2026-09-30 날짜가 모두 예상값과 일치했습니다. 분석 및 결과 이미지 저장 요청은 약 45.6초였습니다.
- 정답/오답 체크 및 오답 4점 입력 → 96점 저장 → 로그아웃/재로그인 → 같은 점수 조회를 확인했습니다.
- 인증 없는 파일 요청 차단, 로그인 사용자의 서명 URL을 통한 crop 조회, 백업 파일 목록 조회를 확인했습니다.
- 검증용 시험과 업로드 이미지를 삭제했습니다. 검증용 계정은 별도로 정리했습니다.
- 브라우저 클릭 E2E는 수행하지 않았습니다. 이번 공개 검증은 HTTP/API로 수행했습니다. 공개 환경에서 대용량 전체 백업 복구와 다중 사용자 부하 검사는 별도로 수행해야 합니다.
